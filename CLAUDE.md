This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Iskra is a one-page static landing site for iskra-project.com.ua. It is a single screen: a logo, a headline, a CTA button that links to a Google Form, a privacy note and an animated star-sky canvas behind them. The site is plain HTML, CSS and an ES module, with no framework or bundler. The user communicates in Ukrainian, and all site copy is Ukrainian.

- Requirements: `spec/SPEC — Iskra технічне завдання для AI-агента.md` (detailed tech spec) and `prd/*.docx`.
- Build report and accepted deviations from the SPEC: `REPORT.md`. Hosting steps (HostiQ, `public_html`): `DEPLOY.md`.

## Commands

```
npm test                                   # Playwright; auto-starts http-server on :8080 serving site/
npx playwright test tests/site.spec.mjs    # one file
npx playwright test -g "iphone-se"         # one viewport/test by name
npm run serve                              # manual preview at http://localhost:8080
npm run build                              # regenerate site/data/sky.json + copy logo/fonts into site/
npm run zip                                # pack site/ contents → dist/iskra-site.zip (the deploy artifact)
```

`npm run zip` refuses to pack while `__FORM_URL__` remains anywhere in `site/`. Use `npm run zip -- --allow-placeholder` for test builds. It excludes `*.zip` files and includes the dotfile `.htaccess`.

After any change in `site/`, run `npm test` and then `npm run zip`. A change only reaches the live site when the user uploads the zip.

## Architecture

- `site/` is the deployable root, served as-is. `index.html` holds all copy. `styles.css` holds the layout. `sky.js` holds everything dynamic:
  - the canvas sky (stereographic projection around the celestial pole, slow rotation, twinkle, meteors, constellation lines with hover tooltips);
  - the `track()` analytics adapter (`cta_click`). No analytics service is wired yet.
- `sky.js` has tuned layout presets (`PRESETS.landscape` / `PRESETS.portrait`). They were chosen so that all six constellations stay visible on common screens; see the table in `REPORT.md` before changing them.
  - The sky starts after `load` and idle, builds its star layer in ~8 ms chunks, and caches the rotated background. This keeps TBT low.
  - On small screens (`min(W,H) < 600`) the sky doesn't rotate.
  - `?still` and `prefers-reduced-motion` make it static.
  - The page must still work with JS off: a `<noscript>` block hides the canvas.
- Generated files in `site/` (do not hand-edit):
  - `site/data/sky.json` is generated by `scripts/build-stars.mjs`, which fetches d3-celestial data from the network.
  - `site/fonts/`, `site/logo/` and `site/CREDITS.txt` are produced by `scripts/copy-assets.mjs` from `logo/` and `node_modules`.
- `logo/` is the brand-asset source (SVG, PNG, favicons, OG image, `colors.css`), built by `logo/build.js`, which uses its own deps and is not part of the npm scripts.

## Tests encode the copy

`tests/site.spec.mjs` asserts the exact visible text of `.hero__title`, `.hero__cta-lead`, `#cta`, `.hero__privacy` and `.footer`, with whitespace normalized. When the user changes site text, update the `TEXTS` map in the same edit.

The meta description and OG description in `index.html` are separate copies of the headline. Ask whether they should change too.

The tests also run across 7 viewports (including WebKit iPhone SE and 320×568). They check that the CTA fits in the first screen, that there is no horizontal scroll, Tab focus, the no-JS mode and size budgets. `tests/perf.spec.mjs` checks frame timing under 4× CPU throttling. Screenshots go to `tests/screenshots/`.
